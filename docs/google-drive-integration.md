# Google Drive Integration Setup Guide

## Overview

The Google Drive integration allows you to automatically ingest photos and collections into your Neon database by uploading files to a Google Drive folder. When files are added to the `upload/` folder, a webhook triggers automatic processing.

## Architecture

```
Google Drive Structure:
alpine-chough/           (root folder)
├── prep/                (staging area - upload files here first)
├── upload/              (watched folder - webhook triggers on changes)
└── processed/           (completed files moved here automatically)
```

**Workflow:**
1. Upload files to `prep/` folder (staging)
2. Move batch from `prep/` → `upload/` when ready
3. Webhook fires automatically → files processed → moved to `processed/`

## Prerequisites

### 1. Google Cloud Service Account

You need a Google Cloud service account with Drive API access:

1. Go to [Google Cloud Console](https://console.cloud.google.com/)
2. Create a new project (or use existing)
3. Enable **Google Drive API** for the project
4. Create a **Service Account**:
   - Go to IAM & Admin → Service Accounts
   - Click "Create Service Account"
   - Give it a name (e.g., "alpine-chough-drive")
   - Grant it "Editor" role (or custom role with Drive access)
5. Create a **JSON key** for the service account:
   - Click on the service account
   - Go to "Keys" tab
   - Add Key → Create new key → JSON
   - Download the JSON file (keep it secure!)

### 2. Share Drive Folder with Service Account

The service account needs access to your Drive folder:

1. Create a folder in Google Drive (or use existing)
2. Right-click → Share
3. Add the service account email (found in the JSON key file, looks like `name@project.iam.gserviceaccount.com`)
4. Give it **Editor** permissions

### 3. Environment Variables

Add these to your `.env.local` file at the project root:

```bash
# Required for setup and operation
DATABASE_URL="postgresql://user:pass@host/db"
GOOGLE_SERVICE_ACCOUNT_JSON='{"type":"service_account","project_id":"...","private_key":"..."}'
GOOGLE_DRIVE_WEBHOOK_SECRET="your-random-secret-min-16-chars"
WEBHOOK_BASE_URL="https://yourdomain.com"

# Optional - if you already have a root folder
GOOGLE_DRIVE_ROOT_FOLDER_ID="your-folder-id"

# These will be generated by the setup script:
GOOGLE_DRIVE_PREP_FOLDER_ID=""
GOOGLE_DRIVE_UPLOAD_FOLDER_ID=""
GOOGLE_DRIVE_PROCESSED_FOLDER_ID=""

# For Vercel Cron (webhook renewal)
CRON_SECRET="another-random-secret"

# Optional - enable collections feature
ENABLE_COLLECTIONS="true"
```

**Important Notes:**
- `GOOGLE_SERVICE_ACCOUNT_JSON`: The entire JSON key file as a single-line string
- `GOOGLE_DRIVE_WEBHOOK_SECRET`: Generate a random string (min 16 chars): `openssl rand -hex 32`
- `WEBHOOK_BASE_URL`: Your deployed app URL (must be HTTPS, no trailing slash)
- `CRON_SECRET`: Another random string for securing the cron endpoint

## Setup Steps

### Step 1: Run the Setup Script

```bash
npm run drive:setup
```

Or with a custom root folder name:
```bash
node scripts/drive-setup.mjs --root-folder-name "my-portfolio"
```

**What it does:**
1. Creates (or finds) the root folder and subfolders (`prep/`, `upload/`, `processed/`)
2. Registers a webhook on the `upload/` folder
3. Stores channel info in the database
4. Prints folder IDs to add to `.env.local`

**Output example:**
```
=== Google Drive Pipeline Setup ===

Creating root folder "alpine-chough"...
  Created folder "alpine-chough" → abc123xyz

Creating subfolders...
  Created folder "prep" → def456uvw
  Created folder "upload" → ghi789rst
  Created folder "processed" → jkl012mno

Registering push notification channel on upload/ folder...
  Channel registered:
    ID       : channel-uuid-here
    Resource : resource-id-here
    Expires  : 2026-06-23T18:00:00.000Z
    Endpoint : https://yourdomain.com/api/drive/webhook

─────────────────────────────────────────────────────
Add these to your .env.local:

GOOGLE_DRIVE_PREP_FOLDER_ID=def456uvw
GOOGLE_DRIVE_UPLOAD_FOLDER_ID=ghi789rst
GOOGLE_DRIVE_PROCESSED_FOLDER_ID=jkl012mno
─────────────────────────────────────────────────────
```

### Step 2: Update .env.local

Copy the folder IDs from the output and add them to your `.env.local`:

```bash
GOOGLE_DRIVE_PREP_FOLDER_ID=def456uvw
GOOGLE_DRIVE_UPLOAD_FOLDER_ID=ghi789rst
GOOGLE_DRIVE_PROCESSED_FOLDER_ID=jkl012mno
```

### Step 3: Deploy Your App

The webhook endpoint must be publicly accessible:

```bash
# Deploy to Vercel (or your hosting platform)
vercel --prod
```

### Step 4: Configure Vercel Cron (Optional but Recommended)

Google Drive webhooks expire after 24 hours. Set up automatic renewal:

1. Create `vercel.json` in your project root:

```json
{
  "crons": [
    {
      "path": "/api/cron/renew-webhook",
      "schedule": "0 0 * * *"
    }
  ]
}
```

2. Add `CRON_SECRET` to Vercel environment variables:
   - Go to Vercel Dashboard → Your Project → Settings → Environment Variables
   - Add `CRON_SECRET` with a random value

3. Redeploy

The cron job runs daily at midnight UTC and automatically renews the webhook.

## Usage

### Upload Individual Photos

1. **Add files to `prep/` folder** in Google Drive
2. **Optional:** Create `metadata.json` in `prep/` with photo details:

```json
{
  "DSC_0001.jpg": {
    "title": "Sunset at the Beach",
    "description": "Golden hour on the coast",
    "date": "2026-06-15",
    "tags": ["landscape", "sunset", "beach"]
  },
  "DSC_0002.jpg": {
    "title": "Mountain Peak"
  }
}
```

3. **Move files from `prep/` → `upload/`** (drag and drop in Drive)
4. **Webhook triggers automatically** → files processed → moved to `processed/`

### Upload Collections (Photo Galleries)

1. **Create a subfolder in `prep/`** (e.g., `prep/my-collection/`)
2. **Add images to the subfolder**
3. **Optional:** Create `collection.json` inside the subfolder:

```json
{
  "title": "Summer 2026",
  "slug": "summer-2026",
  "description": "Photos from our summer trip",
  "cover": "DSC_0001.jpg",
  "order": ["DSC_0001.jpg", "DSC_0003.jpg", "DSC_0002.jpg"]
}
```

4. **Move the entire folder from `prep/` → `upload/`**
5. **Webhook triggers** → collection processed → moved to `processed/`

### Manual Ingestion (Testing/Debugging)

Run the ingestion pipeline manually without waiting for webhook:

```bash
# Dry run - see what would be processed
npm run drive:ingest -- --dry-run

# Actually process files
npm run drive:ingest
```

## Image Processing

Files are automatically:
- **Compressed** using Sharp (same settings as `compress-images.mjs`)
- **Resized** to max 3840px (longest edge)
- **Converted**: WebP stays WebP, others → JPEG
- **Stripped** of all metadata (EXIF, GPS, ICC)
- **Uploaded** to Cloudflare R2; only the public URL is stored in the database

**Supported formats:**
- JPEG (`.jpg`, `.jpeg`)
- PNG (`.png`)
- WebP (`.webp`)

## Webhook Details

### How It Works

1. Google Drive sends a POST to `/api/drive/webhook` when files change in `upload/`
2. The endpoint validates the secret token
3. Processing runs asynchronously (doesn't block the webhook response)
4. Files are downloaded, compressed, inserted into DB, then moved to `processed/`

### Security

- **Token validation**: Webhook requests must include `X-Goog-Channel-Token` header matching your secret
- **HTTPS required**: Google Drive only sends webhooks to HTTPS endpoints
- **Cron authentication**: Renewal endpoint requires `Authorization: Bearer <CRON_SECRET>`

### Webhook Expiration

- Google Drive webhooks expire after **24 hours maximum**
- The setup script requests 23 hours (safety buffer)
- The daily cron job automatically renews before expiration
- If webhook expires, files won't auto-process (use manual ingestion)

## Troubleshooting

### Webhook Not Firing

1. **Check webhook is active:**
   ```bash
   # Query your database
   SELECT * FROM drive_webhook_channel;
   ```

2. **Verify expiration hasn't passed**

3. **Re-run setup:**
   ```bash
   npm run drive:setup
   ```

### Manual Webhook Stop

If you need to stop a webhook manually:

```bash
node scripts/drive-stop-channel.mjs <channelId> <resourceId>
```

Get the IDs from the database or setup script output.

### Files Not Processing

1. **Check logs** in your deployment platform (Vercel logs, etc.)
2. **Run manual ingestion** to see detailed errors:
   ```bash
   npm run drive:ingest
   ```
3. **Verify environment variables** are set correctly
4. **Check service account permissions** on the Drive folder

### Database Errors

Ensure your database schema is up to date:

```bash
# Run schema.sql against your Neon database
psql $DATABASE_URL -f scripts/schema.sql
```

## Database Tables Used

- **`images`**: Image metadata and Cloudflare R2 URL (binary data stored in R2, not the database)
- **`photos`**: Individual photo metadata
- **`collections`**: Collection metadata
- **`collection_images`**: Gallery images (many-to-many)
- **`content_items`**: Ordered list of photos + collections
- **`drive_processed_files`**: Tracks processed Drive file IDs (prevents re-ingestion)
- **`drive_webhook_channel`**: Stores active webhook channel info

## Best Practices

1. **Always stage in `prep/` first** - review files before moving to `upload/`
2. **Use metadata.json** for consistent photo titles/descriptions
3. **Test with dry-run** before processing large batches
4. **Monitor webhook expiration** - ensure cron job is running
5. **Keep service account key secure** - never commit to git
6. **Use collections** for related photo sets (requires `ENABLE_COLLECTIONS=true`)

## Cost Considerations

- **Google Drive API**: Free tier includes 1 billion queries/day
- **Neon Database**: Storage costs for binary images (consider CDN for production)
- **Vercel**: Cron jobs included in Pro plan
